## 1. Live safety — the current TRUE state

### 1.1 Fixed today (verify, don't redo)
`execution-engine.js:717-723` — the load-bearing change:
```js
setAutoEnabled(v) {
  // ADR-003 invariant: auto may never be effectively true while durably halted.
  const durable = v && this._isDurablyHalted();
  this.autoEnabled = !!v && !durable;
  if (durable) console.warn(`[${this.instrumentName}] ⛔ refused to arm auto — halted (${durable}). ...`);
}
```
`_isDurablyHalted()` (`:225-231`) returns `'CONSEC_LOSSES'` when `_consecLosses >= maxConsecLosses`,
`'DRAWDOWN'`, or `'EQUITY_STATE_CORRUPT'`. The boot re-enable at `server.js:7399-7400` now flows through
this guard, so a halted engine stays off. `afternoon-engine.js` carries the identical fix (`:840-846`,
`:832-838`, `:368-369`).

### 1.2 STILL BROKEN — the one halt defect not yet fixed
The **persist-before-update** defect (`APPROVAL-consec-losses-persisted-stale.md`, verdict "SAFE", effort
"LOW") is still present in **both** engines. `execution-engine.js` persists at `:178-186` **before** it
updates the counter at `:188-201`:
```js
178  ... writeJsonSync(file, { capital: this.capital, ...,
183      consecLosses: this._consecLosses, peakEquity: this._peakEquity, ... });   // writes OLD value
188  if (pnl > 0) { ... this._consecLosses = 0; }                                   // update happens AFTER
194  else { this._consecLosses += 1; if (this._consecLosses >= this.maxConsecLosses) { this._haltedReason='CONSEC_LOSSES'; } }
```
So disk is always **one loss stale**. `afternoon-engine.js` has the identical ordering (`:745-754` before
`:756-767`). **Why it matters now:** ADR-003 makes the durable halt a function of the *persisted*
`consecLosses`. Off-by-one means a streak landing exactly on the threshold boots **un-halted and takes one
more losing trade** before re-halting. It does not bite the current NIFTY case (disk 15 ≫ 3), but it
directly weakens the brake ADR-003 was written to make durable. **This is the cleanest, safest next code
change: move the persist block after the update, in both files.**

### 1.3 Two more open safety gaps
- **The API lies about halt state.** `server.js:3182` and `:3420` return `{autoEnabled: !!enabled}` —
  echoing the request, not the engine. POST `enabled:true` to a halted engine and the API says
  `autoEnabled:true` while the engine stays off. ADR-003 / `APPROVAL-halt-reenabled-at-boot.md` release-gate
  condition #2 requires these echo `engine.autoEnabled`; still open.
- **The DAILY_LOSS brake is session-only.** `execution-engine.js:318-328` computes it live from
  `_getDailyPnl()`; `_haltedReason`/`autoEnabled` are **not persisted**, so after a mid-day restart the
  day's realized P&L resets to ~0 and this brake evaporates until it re-breaches. ADR-003 §11 concedes it.

## 2. Data capture — the three cheapest actions, with build specs

This is the platform's #1 constraint and every day of delay is irreversible. The audit turned the three
abstract "cheapest actions" into concrete, evidence-backed builds.

### 2.1 ⏰ TIME-CRITICAL, near-zero cost — save the history being deleted right now
The only live capture is a **premium-only** 1-minute recorder (`server.js:585-593`, stores `[o,h,l,c]` of
`ltp` only — no OI, IV, Greeks). Worse, `_persistOptCandles()` (`server.js:606-607`) runs every 60 s and:
```js
while (files.length > 40) { fs2.unlinkSync(path2.join(_optCandDir, files.shift())); }  // deletes oldest day
```
The July-15 status report names the casualty: *"Save the irreplaceable intraday session —
`data/opt-candles/2026-07-08.json` (the only 99%-complete session) sits in a FIFO-40 dir; ~37 sessions from
silent deletion"* — cost, *"one `cp`."*
- **Do this first, today:** copy the completed sessions out of `data/opt-candles/` to a safe folder, and
  cron the existing rescue mirror (`node option-warehouse.js --every 300`, `option-warehouse.js:141-155`) so
  each day is copied into the never-deleted `data/warehouse/L0_mirror/` before the 40-file purge reaches it.
  **Zero new code.**

### 2.2 Start capturing OI / IV / Greeks (small new module, no live-loop change)
The premium recorder throws away the OI/IV that the chain API *already returns* (`pop-seller.js:183-187`
reads `row.ce.iv`). Build a per-interval **chain-snapshot writer** appending the full row
(`strike, CE/PE ltp, iv, oi, volume, bid, ask, underlying, dte`) to
`data/warehouse/L1_canon/chain_snap/<inst>/<date>.jsonl` via `safe-write.js`. This is H19's L1 snapshot
(`H19-…md:108`) and the only way the research-critical columns begin accruing. Full tick-L0 still needs the
≤5-LOC tee hook (its own approval package).

### 2.3 Outcome logging — stamp entry Greeks, and stop losing trades
No engine stores entry Δ/Γ/Θ/V/IV beside the outcome. The persist functions and their gaps:

| engine | persist fn → file | entry Greeks/IV stored? |
|---|---|---|
| signal-paper | `toJSON()` → `signal-paper-positions.json` | No |
| signal-health | `saveState()` → `data/signal-outcomes.json` | No (7 fields only) |
| pop-seller | `_saveBook()` → `data/pop-book.json` | No — stores `pop`, discards the `delta`/`sigma` `realPoP` computed (`pop-seller.js:135`) |
| strangle | `_saveTrades()` → `data/strangle-trades.json` | No — computes `ivPctAtEntry` (`:320`) but doesn't copy it to the closed record (`:384-394`) |
| confluence-learner | `_save()` → `data/confluence-weights.json` | No (its `greeks`/`iv` keys are 0-100 factor scores) |

Two additive edits (no schema migration): **(a)** stamp the already-computed entry `delta`/`iv` onto each
open record and carry to close — one line per field in `pop-seller.sellPoP`, `strangle` closed record,
`signal-paper.open`. **(b)** the highest-yield action of all: **persist the open book on every mutation** in
`strangle`/`bounce`/`signal-paper` (which lose open positions on restart — `010-…md:390-395`), using the
`safe-write.js` that `execution-engine` already uses. *"Every day this is not done, the platform runs its
only honest experiment — and loses the results."* This is what actually moves 55 → 200 outcomes.

### 2.4 Daily NAV series — confirmed absent, build it
Constraint P3: *"no daily NAV series exists anywhere."* Only per-instrument equity **snapshots** exist
(`execution-engine.js:178-186`, last-write-wins) and a raw realized-P&L `eod-<date>.json`
(`server.js:4318`, no `.bak`, execution-engine books only). Build an append-only
`data/nav/<book>.jsonl` — `{date, book, openingNav, realizedPnlNet, unrealizedPnl, charges, closingNav}` —
written at the existing EOD cadence (`server.js:4315-4316`), net of charges via `charges.js`. ~5 lines per
book per close; unblocks Sharpe/Sortino/Calmar/drawdown.

### 2.5 Buying more history (the doc-backed plan)
`BACKTEST-DATA-PROCUREMENT.md`: build the harness now (₹0), buy **Track A** (underlying 12-yr 1-min) cheap,
gate on **Track B** (option 1-min with **OI + IV**, ATM±15, vendors *TrueData / Global Datafeeds /
iVolatility / AlgoTest*), and only if Track B clears net-of-cost PF > ~1.2 consider a tiny live pilot. But
for *outcomes* there is no shortcut — only persisting paper trades so the forward-test accrues.

## 3. The three missing owners — capital, orders, risk

Thesis confirmed (`ARCHITECTURE-REVIEW.md:387-390`): *"there is no authority in this system. No module owns
capital, no module owns orders, no module owns risk."* Current evidence:

- **Capital:** the boot-order minimal fix **has landed** — `restoreEquity()` now runs *after*
  `_loadConfigOverrides()` (`server.js:3788-3789`, comment `:3782-3787`), so restored equity is no longer
  overwritten. But capital still lives in ≥4 unreconciled places (`equity-nifty/sensex.json`,
  `config-overrides.json:CAPITAL_TOTAL`/`STRANGLE_CAPITAL`) totalling ₹8.8L that *"No component in this
  system adds up"* (`011-…md:75-92`). And **`/api/risk` still reads `process.env.CAPITAL_TOTAL || 500000`**
  (`server.js:6450`) — a third default — so the risk API reports `niftyConsecLosses:0` while the engine
  holds 15.
- **Orders:** **6 `placeOrder()` sites across 3 staged modules** (execution `:540/:678`, afternoon
  `:520/:671`, server `:1916/:7222`) — the review's "8 across 6" counts `stock/` + `amibroker-bridge`, not
  in this tree. **No order manager.** One per-engine boolean `paperMode` (`execution-engine.js:538`) is the
  only guard, reimplemented at each site.
- **Risk:** grep for `totalExposure|portfolioRisk|netDelta` → **0 matches in code.** Only per-engine brakes
  exist, and only in execution/afternoon — **2 of 8 engines**; the ₹7L strangle has none. No cross-engine
  exposure or account-level loss brake.
- **Duplication:** **3 independent Kelly implementations** (`position-sizer.js:73`, `vix-kelly-sizer.js:19`,
  `trade-planner.js:28` — the last reimplements `halfKelly` despite importing from the file that exports
  it) and **GEX twice with opposite dealer sign** (`vol-context.js:89` vs `gex-skew.js:53`). No test
  compares them.

**Migration (read-only-shadow first, per the review):** `account.js` (`AccountLedger`, sole capital owner,
reconcile the 3 balances for 2 weeks) → `order-manager.js` (`submit(intent)→orderId`, wrap the 6 sites one
at a time, move `paperMode` inside) → `RiskEngine` (net delta/vega/notional/day-loss, publish `/api/exposure`
2 weeks, then `check(intent)→allow|reduce|veto` before `OrderManager.submit`). **Cheapest high-value step
still outstanding:** repoint `/api/risk` to read the engines, not env, and persist `_haltedReason`.

## 5. THE ANSWER — what to do next, in order

The ordering rule is unchanged: **safety → data → edge → authority → scale.** But the specific front line
has moved. Do these in order; each is small and most are unblocked.

**P0 — today, minutes, zero-to-low code (no approval needed for the cp/cron):**
1. **`cp` the completed `data/opt-candles/*.json` sessions to safety** and cron the warehouse mirror
   (§2.1). Irreversible loss is happening on a 60-second timer. This is the single most time-critical action
   on the whole roadmap and costs almost nothing.
2. **Restart the server** so today's ADR-003 halt fix actually loads (§0). Until then the running process
   may still be the fail-open build.

**P1 — this week, small + safe (mostly SAFE-verdict approval packages):**
3. **Apply `consec-losses-persisted-stale`** — move persist after update in both engines (§1.2). The one
   halt defect still live; SAFE, LOW effort; it restores ADR-003's durability guarantee.
4. **Repoint `/api/risk` to read the engines, not `process.env`**, and persist `_haltedReason` + intraday
   P&L (§1.3, §3). Makes the existing brakes visible and restart-durable — "under twenty lines."
5. **Close the API echo gate** (`server.js:3182/:3420`) so the halt state stops lying (§1.3).
6. Apply the remaining SAFE packages as convenient: `regime-unknown-vix`, `P1-T3-strategy-config`,
   `signal-health-save-over-corrupt`.

**P1.5 — start now, in parallel (the data that gates everything):**
7. **Persist the open book** in strangle/bounce/signal-paper (§2.3b) — highest-yield single action for
   growing 55 → 200 outcomes.
8. **Stamp entry Greeks + IV onto outcome records** (§2.3a) and **stand up the chain-snapshot writer**
   (§2.2) and the **daily NAV series** (§2.4).

**P2 — get one honest edge number:**
9. Fix the `bt-tv/run.js:265` look-ahead (prompt already written), re-run shift-tested + cost-swept via the
   `bt-validate.js` machinery. Report the PF as measured. **No capital moves until it is > 1 out-of-sample.**

**P3 — build the three owners** (read-only shadows first): `account.js` → `order-manager.js` → `RiskEngine`
(§3). Write the Kelly-equivalence and GEX-sign reconciliation tests alongside.

**P4 — only after an edge is validated AND outcomes ≥ ~200:** dynamic delta-hedging of the seller book,
turn on the Meta-Decision Engine, give the "iron condor" real wings (finding F), and *consider* a tiny gated
live pilot. Not before.

## 6. Bottom line

The good news the July-10 doc could not know: the most dangerous item on its list — the boot fail-open — was
fixed today, and a lot of safety/ledger work has shipped since. So the next move is not one heroic fix; it is
a short, ordered sweep: **save the data that is deleting itself right now (P0), finish the last halt defect
and stop the APIs from lying (P1), and start persisting the paper trades and Greeks that are the only path
to a validated edge (P1.5).** None of these are large. All of them are cheaper than the cost of skipping
them — and one of them (P0) is being lost on a sixty-second timer as you read this.
