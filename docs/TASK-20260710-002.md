## Problem

`eventRiskScore()` feeds the gate on new premium selling. It scored two different kinds of ignorance
as if they were measurements.

## Evidence — VERIFIED

Measured before touching the code, with `getVix` stubbed so no network was involved:

**B — an unreachable India VIX scored like a calm one**

```
vix 20 (elevated)        score  68 level MODERATE  vix.regime NORMAL
vix 14 (calm)            score  59 level MODERATE  vix.regime NORMAL
vix 0 (UNREACHABLE)      score  59 level MODERATE  vix.regime UNKNOWN

unknown vix score === calm vix score ?  true
unknown vix level === calm vix level ?  true  -> MODERATE
does the result flag the unknown?       false
```

The engine already *knew* — `vix.regime` said `UNKNOWN`. The score ignored it.

**C — an unrecognised event type was silently downgraded to a dividend**

```
RBI_POLICY    known: true   weight  90   score  90   level HIGH   flagged? false
RBI           known: false  weight  30   score  30   level LOW    flagged? false
BUDGET        known: true   weight  95   score  95   level HIGH   flagged? false
BUDGET_2026   known: false  weight  30   score  30   level LOW    flagged? false
```

A **budget day** typed `BUDGET_2026` reads as **LOW**. This suite's own first draft typed `RBI`
instead of `RBI_POLICY` and scored an RBI policy day as `OTHER`. The defect caught its own author.

## Root Cause

**B.** `const vixLift = vix.value ? … : 0`. `getVix()` is a Yahoo network call inside `catch (_) {}`;
on failure `value` is `0`. India VIX is never 0, so a zero means *no reading*, not *no volatility*.
A lift of `0` is a measurement — the measurement of a perfectly calm market.

**C.** `TYPE_WEIGHT[e.type] || TYPE_WEIGHT.OTHER`. A type never seen before — a renamed upstream feed,
a typo, a new event class — is assigned the weight of a dividend. Nothing is logged, nothing is flagged.

Both are the same rule broken: **an absent value is replaced by a value on the same scale as a
measurement.** `Unknown ≠ Zero. Unknown ≠ Neutral.`

## Diff Summary

```js
// B
- const vixLift = vix.value ? Math.min(20, Math.max(0, (vix.value - 14)) * 1.5) : 0;
+ const vixKnown = Number.isFinite(vix.value) && vix.value > 0;
+ const vixLift  = vixKnown ? Math.min(20, Math.max(0, vix.value - 14) * 1.5) : null;

// C
+ const unknownTypes = [...new Set(up.map(e => e.type).filter(t => TYPE_WEIGHT[t] === undefined))];

// both
+ const unknowns = [];
+ if (!vixKnown) unknowns.push('indiaVix');
+ if (unknownTypes.length) unknowns.push(...unknownTypes.map(t => `eventType:${t}`));
+ const level = unknowns.length ? 'UNKNOWN' : score >= 75 ? 'HIGH' : … : 'CALM';
```

**No number was invented.** The event component *is* measured, so `score` still reports it and is
byte-for-byte unchanged; the OTHER weight remains the floor for an unknown type, because no honest
weight exists. What was **withdrawn is the claim about the level**: a composite risk level computed
from a component nobody observed is a false statement wearing a measurement's clothes.

### Why `score` was deliberately left alone

`server.js:5779` and `:6170` consume `.score` numerically. Returning `null` there would flow into
`Number(…) || 0`, become **0**, and then `cEvent = 100` — *maximally safe to sell*. Failing closed on
`score` would have failed **open** one layer up. So the score keeps its measured part, the level tells
the truth, and the real fix for the numeric path is the protected package
`docs/APPROVAL-regime-unknown-vix.md`. `level` is consumed only as a display label (`server.js:5401`),
which is why it can carry `UNKNOWN` safely.

## Risk

**LOW–MEDIUM.** Behaviour changes in one direction only: the engine now refuses to assert a risk level
it cannot support.

- `level` gains a new value, `'UNKNOWN'`. Its only consumer is `server.js:5401`, which renders it as a
  text label. **No numeric consumer reads `level`.**
- `score` is unchanged for every input. Verified by assertion.
- New fields — `vixUnknown`, `unknownTypes`, `unknowns`, `vixLift` — are **additive**. Every field the
  old result carried is still carried, pinned by a rollback assertion.
- `vix.value` is now `null` rather than `0` when unknown. Any dashboard panel rendering it must show an
  em-dash, not `0`. **Not yet audited — see Future work.**
